BDApi ​

Java library for creating and animating Block Displays on Paper (1.21.11+). Supports two backends: server-side Block Displays (Paper) and client-side Block Displays (PacketEvents).

Installation ​

kotlin
repositories {
    maven("https://maven.rscomeback.fr/releases")
}
dependencies {
    implementation("fr.redsavant:bdapi:1.0.0-beta.1")
}

Shadow the JAR into your plugin.

Requirements ​

  • Paper 1.21.11+
  • Java 21+
  • PacketEvents (optional, only required for the PACKET_EVENTS backend)

Initialization ​

java
@Override
public void onEnable() {
    BDApi.init(this);
}
@Override
public void onDisable() {
    BDApi.shutdown(true); // true = removes all entities
}

Advanced configuration ​

java
BDApi.init(this, BDApiConfig.builder()
        .defaultBackend(DisplayBackend.PAPER)
        .packetSender(mySender)    // Custom sender (optional)
        .build());

MethodDescriptionDefault
.defaultBackend(DisplayBackend)Default backend for all displays
PAPER

Backends ​

BDApi exposes two backends via the DisplayBackend enum:

BackendDescription
PAPERServer-side Bukkit/Paper Block Display. Visible to all eligible players, persists as an entity in the world. Does not require PacketEvents.
PACKET_EVENTSClient-side (fake) Block Display. No Bukkit entity on the server; the display is sent to specific players via packets. Requires PacketEvents installed and initialized.
If PACKET_EVENTS is requested while PacketEvents is not available, spawning throws an IllegalStateException.

Creating a Block Display ​

java
// Default backend (PAPER)
DisplayCrate crate = BDApi.get().displays().create()
        .at(location)
        .block(Material.DIAMOND_BLOCK)
        .scale(1.5f)
        .spawn();
// PacketEvents backend, visible to a specific player
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .viewer(player)
        .at(location)
        .block(Material.EMERALD_BLOCK)
        .spawn();
// PacketEvents backend, visible to all online players
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .global()
        .at(location)
        .block(Material.GOLD_BLOCK)
        .spawn();

Anchors ​

The anchor controls the pivot point for scale and rotation. Default is CENTER: the display pivots around its center and does not drift during scaling/rotation.

java
// Displayed centered on the block (default)
displays.create().at(loc).block(Material.STONE).scale(2f).spawn();
// Displayed anchored at the corner (raw Minecraft behavior)
displays.create().anchor(Anchor.CORNER).at(loc).block(Material.STONE).scale(2f).spawn();
AnchorBehavior
CENTERScale/rotation pivot around the block's center. Scale 1 with no rotation = normal block.
CORNERRaw Minecraft behavior: pivots at the block's minimal corner.
Both backends share the same coordinate logic.

Animation ​

java
crate.animate()
    .moveTo(targetLocation)     // Move to a Location
    .rotateTo(0, 180, 0)       // Target rotation (degrees, Euler ZYX)
    .scaleTo(2f, 2f, 2f)       // Target scale
    .translateTo(0, 1, 0)      // Target translation
    .duration(2, TimeUnit.SECONDS)
    .easing(Easing.EASE_OUT)
    .onComplete(() -> System.out.println("Done!"))
    .play();

Physics ​

java
crate.physics()
    .gravity()              // Default gravity (0.08)
    .gravity(0.15)          // Custom gravity
    .bounce(0.4)            // Bounce (0 = none, 1 = perfect)
    .drag(0.02)             // Air resistance (default: 0.02)
    .velocity(0, 0.5, 0)   // Initial velocity
    .onLand(crate -> {      // Callback on landing
        crate.remove();
    })
    .start();

Behavior:
  • Gravity pulls downward (terminal max: -3.0)
  • The ground is detected via Block.isSolid()
  • Bouncing stops when the bounce velocity < 0.05

Timeline ​

Executes a sequence of animations one after another.

java
crate.timeline()
    .moveTo(pos1, 1, TimeUnit.SECONDS)
    .rotate(0, 180, 0, 500, TimeUnit.MILLISECONDS)
    .scale(2, 1, 2, 500, TimeUnit.MILLISECONDS)
    .wait(1, TimeUnit.SECONDS)
    .moveTo(pos2, 2, TimeUnit.SECONDS)
    .loop(true)     // Loops the sequence
    .play();

Groups ​

Manages several displays as a single unit.

java
DisplayGroup group = BDApi.get().displays().group()
    .at(origin)                              // Origin point
    .add(BDApi.get().displays().create()     // Add via builder
            .block(Material.STONE)
            .translate(-1, 0, 0))
    .add(existingCrate)                      // Add an existing crate
    .add(builder, 2.0, 0.0, 0.0)           // Add with explicit offset
    .spawn();                                // Spawn everything
// Modify all members
group.transformAll(transform -> {
    transform.scale(1.5f).apply();
});
// Remove all members
group.remove();
// Retrieve all crates
List<DisplayCrate> crates = group.crates();

DisplayGroup ​

MethodDescription
.at(Location)Sets the group's origin
.add(BlockDisplayBuilder)Adds a display (offset computed from the origin)
.add(BlockDisplayBuilder, x, y, z)Adds a display with an explicit offset
.add(DisplayCrate)Adds an existing crate
.spawn()Spawns all members not yet spawned
.transformAll(Consumer<TransformHandle>)Applies a transformation to all members
.remove()Removes all members
.crates()List of the group's DisplayCrate instances

Effects ​

Explosion effect ​

java
BDApi.get().effects().explosion()
    .at(location)
    .power(2f)              // Power (default: 1)
    .particles(true)        // Particles enabled (default: true)
    .spawn();

Spawns EXPLOSION_EMITTER + FLAME particles + ENTITY_GENERIC_EXPLODE sound.

Meteor effect ​

java
DisplayCrate meteor = BDApi.get().effects().meteor()
    .at(targetLocation)         // Target
    .fromHeight(150)            // Spawn height (default: 100)
    .size(5)                    // Size (default: 2)
    .block(Material.MAGMA_BLOCK)// Material (default: MAGMA_BLOCK)
    .impact(true)               // Particles on impact (default: true)
    .spawn();

Creates a display that falls toward the target with gravity. On impact: EXPLOSION + LAVA particles + sound, then the entity is removed. ​

PacketEvents — Details ​

Auto-detection ​

If PacketEvents is installed and initialized on the server, BDApi automatically uses it as the sender for the PACKET_EVENTS backend. Otherwise, you can provide a custom sender via BDApiConfig.

Per-player visibility ​

PacketEvents displays support per-player visibility:

java
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .global()            // Visible to all online players
        .at(location)
        .block(Material.DIAMOND_BLOCK)
        .spawn();
crate.show(player);           // Makes it visible to a player
crate.hide(player);           // Hides it for a player
crate.isVisibleTo(player);    // Checks visibility
Set<UUID> viewers = crate.viewers(); // List of viewers

Global displays are sent to online players on spawn, and to players who connect later. Viewer state is cleared on disconnect.

Limitations ​

  • The PACKET_EVENTS backend requires PacketEvents installed and initialized.
  • Client-side displays are not real entities: no collision, no persistence, visible only to their viewers.
  • Per-player visibility only applies to the PACKET_EVENTS backend.
