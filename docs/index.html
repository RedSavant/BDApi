BDApi ​

Bibliothèque Java pour créer et animer des Block Displays sur Paper (1.21.11+). Supporte deux backends : les Block Displays serveur (Paper) et les Block Displays client-side (PacketEvents).

Installation ​

kotlin
repositories {
    maven("https://maven.rscomeback.fr/releases")
}
dependencies {
    implementation("fr.redsavant:bdapi:1.0.0-beta.1")
}

Shadow le JAR dans votre plugin.

Prérequis ​

  • Paper 1.21.11+
  • Java 21+
  • PacketEvents (optionnel, uniquement requis pour le backend PACKET_EVENTS)

Initialisation ​

java
@Override
public void onEnable() {
    BDApi.init(this);
}
@Override
public void onDisable() {
    BDApi.shutdown(true); // true = supprime toutes les entities
}

Configuration avancée ​

java
BDApi.init(this, BDApiConfig.builder()
        .defaultBackend(DisplayBackend.PAPER)
        .packetSender(monSender)    // Sender personnalisé (optionnel)
        .build());

BDApiConfig ​

MéthodeDescriptionDéfaut
.defaultBackend(DisplayBackend)Backend par défaut pour tous les displays
PAPER
.packetSender(PacketDisplaySender)Sender packet personnaliséAuto-détecté via PacketEvents

Backends ​

BDApi expose deux backends via l'enum DisplayBackend :

BackendDescription
PAPERBlock Display serveur Bukkit/Paper. Visible par tous les joueurs éligibles, persiste comme entity dans le monde. Ne nécessite pas PacketEvents.
PACKET_EVENTSBlock Display client-side (fake). Aucune entity Bukkit sur le serveur ; le display est envoyé à des joueurs spécifiques via des packets. Nécessite PacketEvents installé et initialisé.
Si PACKET_EVENTS est demandé alors que PacketEvents n'est pas disponible, le spawn lance une IllegalStateException.

Créer un Block Display ​

java
// Backend par défaut (PAPER)
DisplayCrate crate = BDApi.get().displays().create()
        .at(location)
        .block(Material.DIAMOND_BLOCK)
        .scale(1.5f)
        .spawn();
// Backend PacketEvents, visible par un joueur spécifique
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .viewer(player)
        .at(location)
        .block(Material.EMERALD_BLOCK)
        .spawn();
// Backend PacketEvents, visible par tous les joueurs en ligne
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .global()
        .at(location)
        .block(Material.GOLD_BLOCK)
        .spawn();

Anchors (ancrage) ​

L'anchor contrôle le point pivot pour le scale et la rotation. Par défaut CENTER : le display pivote autour de son centre, il ne dérive pas lors du scaling/rotation.

java
// Affiche centré sur le bloc (défaut)
displays.create().at(loc).block(Material.STONE).scale(2f).spawn();
// Affiche ancré au coin (comportement Minecraft brut)
displays.create().anchor(Anchor.CORNER).at(loc).block(Material.STONE).scale(2f).spawn();
AnchorComportement
CENTERScale/rotation pivotent autour du centre du bloc. Scale 1 sans rotation = bloc normal.
CORNERComportement Minecraft brut : pivot au coin minimal du bloc.
Les deux backends partagent la même logique de coordonnées.

Animation ​

java
crate.animate()
    .moveTo(targetLocation)     // Déplacer vers une Location
    .rotateTo(0, 180, 0)       // Rotation cible (degrés, Euler ZYX)
    .scaleTo(2f, 2f, 2f)       // Scale cible
    .translateTo(0, 1, 0)      // Translation cible
    .duration(2, TimeUnit.SECONDS)
    .easing(Easing.EASE_OUT)
    .onComplete(() -> System.out.println("Terminé !"))
    .play();

Modifie immédiatement la transformation sans animation.

Physique ​

java
crate.physics()
    .gravity()              // Gravité par défaut (0.08)
    .gravity(0.15)          // Gravité custom
    .bounce(0.4)            // Rebond (0 = aucun, 1 = parfait)
    .drag(0.02)             // Résistance de l'air (défaut: 0.02)
    .velocity(0, 0.5, 0)   // Vitesse initiale
    .onLand(crate -> {      // Callback à l'atterrissage
        crate.remove();
    })
    .start();

PhysicsBuilder ​

MéthodeDescription
.gravity()Active la gravité (0.08)
.gravity(double)Gravité custom
.bounce(double)Coefficient de rebond
.drag(double)Frottement de l'air
.velocity(Vector)Vitesse initiale (Bukkit Vector)
.velocity(double, double, double)Vitesse initiale (x, y, z)
.onLand(Consumer<DisplayCrate>)Callback au toucher du sol
.start()Active la physique
Comportement :
  • La gravité tire vers le bas (max terminal: -3.0)
  • Le sol est détecté via Block.isSolid()
  • Le rebond se termine quand la vitesse de rebond < 0.05

Timeline ​

Exécute une séquence d'animations les unes après les autres.

java
crate.timeline()
    .moveTo(pos1, 1, TimeUnit.SECONDS)
    .rotate(0, 180, 0, 500, TimeUnit.MILLISECONDS)
    .scale(2, 1, 2, 500, TimeUnit.MILLISECONDS)
    .wait(1, TimeUnit.SECONDS)
    .moveTo(pos2, 2, TimeUnit.SECONDS)
    .loop(true)     // Boucle la séquence
    .play();

.scale(float x, float y, float z, long, TimeUnit)Étape de scale
.wait(long, TimeUnit)Pause entre les étapes

.stop()Arrête la timeline en cours

Groupes ​

Gère plusieurs displays comme une unité.

java
DisplayGroup group = BDApi.get().displays().group()
    .at(origin)                              // Point d'origine
    .add(BDApi.get().displays().create()     // Ajout via builder
            .block(Material.STONE)
            .translate(-1, 0, 0))
    .add(existingCrate)                      // Ajout d'un crate existant
    .add(builder, 2.0, 0.0, 0.0)           // Ajout avec offset explicite
    .spawn();                                // Spawn tout
// Modifier tous les membres
group.transformAll(transform -> {
    transform.scale(1.5f).apply();
});
// Supprimer tous les membres
group.remove();
// Récupérer tous les crates
List<DisplayCrate> crates = group.crates();

DisplayGroup ​

MéthodeDescription
.at(Location)Définit l'origine du groupe
.add(BlockDisplayBuilder)Ajoute un display (offset calculé depuis l'origine)
.add(BlockDisplayBuilder, x, y, z)Ajoute un display avec offset explicite
.add(DisplayCrate)Ajoute un crate existant
.spawn()Spawn tous les membres non encore spawnt
.transformAll(Consumer<TransformHandle>)Applique une transformation à tous les membres
.remove()Supprime tous les membres
.crates()Liste des DisplayCrate du groupe

Effets ​

Effet Explosion ​

java
BDApi.get().effects().explosion()
    .at(location)
    .power(2f)              // Puissance (défaut: 1)
    .particles(true)        // Particules activées (défaut: true)
    .spawn();

Spawn des particules EXPLOSION_EMITTER + FLAME + son ENTITY_GENERIC_EXPLODE.

Effet Météore ​

java
DisplayCrate meteor = BDApi.get().effects().meteor()
    .at(targetLocation)         // Cible
    .fromHeight(150)            // Hauteur de spawn (défaut: 100)
    .size(5)                    // Taille (défaut: 2)
    .block(Material.MAGMA_BLOCK)// Matériau (défaut: MAGMA_BLOCK)
    .impact(true)               // Particules au contact (défaut: true)
    .spawn();

Crée un display qui chute vers la cible avec gravité. À l'impact : particules EXPLOSION + LAVA + son, puis l'entity est supprimée. ​

PacketEvents — Détails ​

Auto-détection ​

Si PacketEvents est installé et initialisé sur le serveur, BDApi l'utilise automatiquement comme sender pour le backend PACKET_EVENTS. Sinon, vous pouvez fournir un sender personnalisé via BDApiConfig.

Per-player visibility ​

Les displays PacketEvents supportent la visibilité par joueur :

java
DisplayCrate crate = BDApi.get().displays().create()
        .backend(DisplayBackend.PACKET_EVENTS)
        .global()            // Visible par tous les joueurs en ligne
        .at(location)
        .block(Material.DIAMOND_BLOCK)
        .spawn();
crate.show(player);           // Rend visible à un joueur
crate.hide(player);           // Masque pour un joueur
crate.isVisibleTo(player);    // Vérifie la visibilité
Set<UUID> viewers = crate.viewers(); // Liste des viewers

Les displays globaux sont envoyés aux joueurs en ligne au spawn, et aux joueurs qui se connectent plus tard. Le viewer state est nettoyé à la déconnexion.

Limites ​

  • Le backend PACKET_EVENTS nécessite PacketEvents installé et initialisé.
  • Les displays client-side ne sont pas de vraies entities : pas de collision, pas de sauvegarde, visibles uniquement par leurs viewers.
  • La visibilité par joueur s'applique uniquement au backend PACKET_EVENTS.

Résumé de la hiérarchie ​

BDApi (singleton)
├── BDApiConfig
│   ├── defaultBackend: DisplayBackend
│   └── packetSender: PacketDisplaySender
├── Displays
│   ├── create() → BlockDisplayBuilder → DisplayCrate
│   └── group()  → DisplayGroup
└── Effects
    ├── explosion() → ExplosionEffect
    └── meteor()    → MeteorEffect
DisplayCrate
├── .handle()     → DisplayHandle (PaperDisplayHandle | PacketDisplayHandle)
├── .animate()    → AnimationBuilder → .play()
├── .physics()    → PhysicsBuilder  → .start()
├── .timeline()   → Timeline        → .play()
└── .transform()  → TransformHandle → .apply()
DisplayHandle (interface)
├── PaperDisplayHandle   → délègue à BlockDisplay Bukkit
└── PacketDisplayHandle  → envoie des packets via PacketDisplaySender
